## 0. 一段落でいうと

5チェーン(base / optimism / arbitrum / polygon / avalanche)の DEX を監視し、**元手ゼロ**(フラッシュスワップ)で
価格差を取る裁定 bot。Railway で稼働、`main` へのマージで自動デプロイ。

**現状の実力(実測):裁定は1回 $0.005、1日 $0.25〜0.80。** 深いプールは価格差が0bps、浅いプールは
$1〜30しか吸えず、掛け算の答えが常に小さい(競争で価格差そのものが消える)。
**主軸は Aave 清算へ移す方針**(固定ボーナス5〜10%は競争で削れない。base の実測で $1,000超が1日2回)。
清算のコントラクト機能は**書いてあるが未配置**(§8)。

## 2. 1本の取引が通る道

```
[イベント] Sync / Swap を WebSocket で受信(dex-onchain-realtime)
    ↓ 地図の準備量を更新(pool-registry)
[経路計算] そのプールを含む2段・3段の経路を組み直す(opportunity-scanner.scanForChangedPool)
    ├ 一時除外中のプールを含む → 捨てる(飛ばした経路として数える)
    ├ V3を1段も含まない → 捨てる(V2だけの経路は判定しない)
    ├ 投入額を探索(findBestAmount。上限は 取引上限 と 価格表の信用できる範囲 の小さい方)
    └ 粗利プラスなら handleOpportunity へ
[handleOpportunity](index.js) — 捨てる道は7つ、**全て大物の台帳に記録される**
    ① 無効なプール(永久 or 一時)  ② 税トークン  ③ 冷却中  ④ 罠(利回り20%超)
    ⑤ 最低利益未満($0.01)         ⑥ 同じ経路を送信中  ⑦ 同じプールが使用中/同時送信の上限(3本)
    ↓
[executeOpportunity](execute-opportunity)
    1. simulateRoute(eth_call)と estimateGas を**同時に**投げる
       ├ 取り消しの中身が SimulationResult → returned/owed が分かる
       ├ K() 等 → 手数料の前提が低い → 手数料を直読み(pool-fee-onchain)し直す
       └ 赤字 → 段ごとの答え合わせ(公式Quoter と突き合わせ)→ 表の上限を学習 / 責任の判定
    2. 実測ガスで純利益を**確かめ直し**(下回れば送らない)
    3. 送信 → 確定待ち
       ├ 成立 → 記録簿・成功回数(取引上限が上がる)
       └ wait で取り消し = **他人に先を越された**(失敗には数えない)
```

**チェーン上の守り(最後の砦):** コントラクトが `returned >= owed + minProfit` を要求する。
ここを通らなければ取引ごと取り消され、失うのはガス代だけ。全段の受取量は残高の差で測る(税トークンでも壊れない)。

## 3. 起動の順序(`main()`)

1. HTTP 画面を起動
2. `RUN_MAINNET_DEPLOY` / `RUN_POOL_SURVEY` が設定されていればその作業(普段は無い)
3. 記録簿を読む → 生存ログ開始 → ガス代を取得
4. **WebSocket の購読開始**(`startOnchainFeeds`)
5. **プール地図の準備**(`preparePoolMap`: 保存から復元 → 各チェーンの準備量・桁数・価格)
6. コントラクトの版を確認(`checkContractVersions`。`simulateRoute` が返るかを実測)
7. optimism / base で pending(Flashblocks)の可否を実測
8. 周期処理を全て開始(§4)
9. Aave の Pool が応答するチェーンだけ清算の見張り開始
10. 10秒後に全経路のスキャン開始

## 6. 生存ログの読み方(1分ごと)

```
実行N/M        … 成立N件 / 失敗M件(このデプロイの通算)
内訳[…]        … 捨てた理由(無効/冷却/罠/下限/送信中/見送)
失敗段階[…]    … simulate / feeMismatch(K検算) / wait(先を越された) / estimateGas …
受信[…]        … WebSocket で届いたイベント数(**枠に課金される**)
先読み[…]      … Flashblocks の先行(base は押し出し、optimism は取得)
手数料N(残M 直読みK 読めずJ 学習I) … V2手数料の実測状況
枠[…毎分N 月末見込M%]  … RPC の枠。**受が7割**。70%で発見が自動停止
V3表[確認N 上限制限M(今K本) …] … 価格表の検証と上限
一時除外[のべN 今M 飛ばした経路K本(のべJ回)] … **本数と回数は別物**(回数はイベントごとに数え直す)
手数料実測[判明N 取引なしで保留M …]
外した[永久N 一時M 先越されK]   … 先越され = 競争に負けた(失敗ではない)
大物[検知N 成立M 得た$X 逃した見込み$Y] … $0.10以上の機会の行方
清算[名簿N 見張りM 見つけたK 他者J 回復I 実績L件(小口p% 極小q%)]
取引量[最適は上限のX% 4倍で利益Y% 上限張付Z 標本N] … **上限を上げる意味があるかの答え**
送信の収支[chain 勝N/負M ±$X]  … **取った額 − 先越されで失ったガス代**。ここがマイナスなら要見直し
清算AVAX[名簿N(遡りX%) 要注意M 候補C 他者T 回復R 価格更新P(即Q) WS接続 RPCn]
```

## 7. お金と枠を守る仕組み(一覧)

| 層 | 仕組み | 値 |
|---|---|---|
| チェーン上 | `returned >= owed + minProfit` | 最後の砦 |
| 送信前 | `simulateRoute` + `estimateGas` を同時に | 赤字なら送らない |
| 送信前 | 実測ガスで純利益を確かめ直す | `MIN_PROFIT_USD=0.01` |
| 送信前 | **手数料負けの線**(粗利がガス代を上回るか)。裁定も清算も同じ | `$0.00001`(純利はガス代を引いた後の値) |
| 送信時 | 鎖上の最低利益は**取り消しが得になる境目**(ガス代の10%)。50%固定をやめた | `REVERT_GAS_SHARE=0.10` |
| 判定 | 罠(利回り20%超は幻) | `MAX_SANE_RETURN_RATIO=0.20` |
| 判定 | 税トークン(手数料100bps超は永久除外) | `TAX_TOKEN_FEE_BPS=100` |
| 判定 | 価格表の信用できる上限(過大が20bps超で投入額を制限) | `VERIFY_DROP_TABLE_BPS=20` / `LEARN_CAP_BPS=20` |
| 失敗後 | 冷却(同じ経路を10分) | `FAILURE_COOLDOWN_MS` |
| 失敗後 | **一時**無効(本物の失敗が30分に3回で60分)。**先を越された(wait)は数えない** | `FAILURE_WINDOW_MS` / `FAILURE_DISABLE_MS` |
| 失敗後 | 一時除外(**地図の誤り**が30bps超、6時間に2回で60分) | `BLAME_MIN_BPS=30` |
| 枠 | 月末見込70%で新しいプールの採用を止める | `SCOUT_QUOTA_STOP_PCT=70` |
| 投入額 | 成功回数で上限を段階的に上げる | `trade-cap.js` |

**永久に外してよいのは「性質として変わらないもの」(税・詐欺)だけ。** 送信失敗や価格の動きは永久の理由にしない。

### 8-1. **今日、実測で決着した3つ。もう一度調べ直さないこと**

| 問い | 答え | 根拠(実測) |
|---|---|---|
| **メインネットへ移れば取引量は増えるか** | **いいえ。行き止まり** | 価格差が3bps超えた瞬間を24件、Quoterに「$5,000/$50,000入れたら実際いくら返るか」と聞いた。**24件すべて赤字**。しかも**「同ブロックでは黒字だったが消えた」が0件** = 速さの問題ですらない。見えていた歪み(最大606bps)は**板の無い価格帯**の値 |
| **他チェーンの清算は取れるか** | **いいえ。届く範囲は$0.02** | HF<1 を16人見つけ、**16人全員の計画を実際に立てた**。合計の粗利が**$0.02**。中身は `cbBTCの借金$0.03` のようなダスト。`他者0`(=見つけた人が他人に取られた回数)がずっと0 = **レースに負けているのではなく、レースを見ていない**(巡回10分 vs 専業50ms) |
| **取引上限を上げれば1回の取引量は増えるか** | **いいえ。プールの深さが天井** | 上限は既に**$2,000**(成功回数で最上段まで上がっていた)。実際に送る経路の中央値は**$1.15〜2.99**。上限に張り付いた回数は98万回中**0〜9回**。4倍にすると利益**−1,400〜−4,100%** |
| **arbitrum は速さを磨けば勝てるか** | **いいえ。競売に出ない限り構造的に不可** | arbitrum は既に素のFCFSではなく **Timeboost** が稼働。60秒ごとの**封印入札(2位価格)**で「即時レーン」を1者が落札し、**それ以外の取引は既定で200ms遅延**される。我々は毎回200msの固定ハンデを背負っており、**優先手数料では順番が1つも変わらない**。速さへの投資では解決しない(公式文書で確認) |
| **`[ふるい]` の `利益[$0.1〜1 / $1超]` は狙える機会か** | **いいえ。2重に水増しされた数字** | ①`estimateNetUsd` は**V3の段も x·y=k(V2の式)で近似**する。V3は流動性が狭い帯に集中しているので、大きな投入額では受取量を**構造的に過大評価**する(「多めに出して本物を落とさない」という*意図した*設計)。②`routeNet`/`keepSample` は**起動以降の最高値の据え置き**で、現在値ではない。**この2つの箱を「取り逃した金」と読んではいけない** |

**メインネットの深さ調査(参考値)**: `USDC→WETH(0.30%)` は10bpsの歪みで最適$40,748・粗利$20.37、ガス$0.90、採算の分かれ目**2.10bps**。**器は大きいが水が来ない**、というのが結論。

**50ms級の設備を入れる場合の月額**(2026年9月22日に調査): 専用RPCのみ $1,800〜2,700/月(**これでも50msには届かない**)/ 自前ノード+ベアメタル $700〜1,400/月 / 専業と同等(コロケーション)$2,000〜5,000/月+構築3〜6ヶ月。**清算市場の全体が月$4,650、損益分岐は「市場の22%を取れるか」。現時点では投資しない判断。**

#### 入札額が高すぎる疑い(2026年9月22日 12:20 JST、**オーナーの判断待ち**)

## 10. 方針の転換(2026年9月22日 16:00 JST、オーナーと議論して)

### 10-1. なぜ転換するか — 原子的DEX裁定の天井は実測で出た

- **浅いプール** … 価格差は残るが$1しか入らない

**`深さ × 価格差` がほぼ一定で小さい。** これは競争均衡の必然で、腕の問題ではない。

外部の実測(2026年3月)も同じ:**同一チェーン裁定の利益機会の78%を上位12社が取得**、

**$50/日まで320倍、月$1万まで2,131倍。範囲拡大で届くのは10倍(=$1〜2/日)まで。**

### 10-2. 何が間違っていたか

裁定・清算・チェーン間裁定 — **全部「速さ」か「元手」で勝負する土俵**だった。我々はどちらも持っていない。

> **裁定の利幅は競争でゼロに削られる。注文フローの利幅は削られない**
> — ユーザーは「すぐ約定すること」に対価を払っているため。

### 10-3. UniswapX の filler(**本命。着手済み**)

一次情報で確認した事実:

- **UniswapX には権限が要る役と要らない役がある。** quoter(RFQで値段を聞かれ、勝つと**独占約定権**)は
  Uniswap Labs の審査が要る。**filler(注文を約定させる役)は permissionless で、
  コントラクトレベルの最低ステークは存在しない**
- 注文は**公開API**から誰でも取れる(`GET api.uniswap.org/v2/orders`、**APIキー不要**)
- filler は `IReactorCallback` を実装した Executor を置き、**入ってきた通貨で出す通貨を用意する**。
  流動性の出どころは自由で、**公式の例 `SwapRouter02Executor` は Uniswap V2/V3 から調達している**
- 展開チェーンに **polygon / base / optimism / arbitrum / avalanche が全部含まれる**
  = **我々が既にプール地図を持っているチェーンそのもの**
- 価格はダッチオークションで減衰する。**340msの一発勝負ではなく、
  「自分が黒字になる価格まで待てる」時間軸がある** → 値付けの質が効く余地がある
  (ただし「低遅延のfillerほど多く取る」とも明記されており、**速さが無関係にはならない**)

**なぜ既存資産が活きるか:** 数週間かけて作った「この通貨をこの量入れたら全プールで最良いくら返るか」の
エンジンは、裁定では**答えがほぼ毎回『儲からない』**なので1日$0.15の価値しかない。
**値付けに回すと、そのエンジン自体が商品になる。**

### 10-4. Solana(**一度却下したが、オーナーの指摘で測ることにした**)

市場は大きい:**Jito経由の searcher 利益が累計$4.8億、月$3,000〜5,000万**。

「参入障壁がはるかに低く、独立開発者や小規模チームが試せる」。

**しかし決定的な一文がある:**

> 「その$7.2億の大半を取った searcher は、競合より高度な戦略を running していたのではない。
>  **多くの場合、より良いインフラを running していた。** 戦略の質は、いまや**インフラの質に次ぐ**」

### 10-6. 元手$500について(オーナーの申告)

**$500 では取引に使わない方がよい。**

- 減らせないリスクが残る:①が通って②が通らない / 2本の間に価格が動く / **ブリッジの停止・ハック** / デペッグ

### 10-7. Solana の計測(`scripts/solana-probe.js`、**第1段・鍵不要・リスクゼロ**)

**問い:** Solana に「取引されているのに誰も裁定していないコイン」はあるか。

**測り方:** DexScreener(無料・認証不要・300req/分)から同じトークンの複数DEXのプールを取り、
  ・**両方に出来高がある**(片方が死んでいれば売り抜ける相手が居ない)
  ・**両方に流動性がある**(実際に入る)
に絞って価格差を出す。そして**同じ価格差が次の観測でも残っているか**を数える。

> **残る = 誰も取っていない = 放置されている。** これが問いへの直接の答え。

```
Solana計測[N回目 銘柄X ペアY 比較可Z 30bps超K(**連続で残るJ**) 対照SOL/USDC Wbps 最大Vbps(TKN/SOL raydium→meteora 薄い側$L 24h$M 連続n)]
```

**対照群を必ず見る。** 既定のトークンに SOL/USDC を入れてあり、ここに継続的な差が出たら
**測り方が壊れている**(主要ペアは誰もが見ているので差は残らないはず)。

**これは「ふるい」であって「お金」ではない。** DexScreener の価格は各DEXの観測値で、
実際に約定できる額ではない。**我々は今日この罠を踏んでいる**(§8-1)。
ここで分かるのは**「どこを見るべきか」**だけ。

**第2段(未実装・オーナーの作業が要る):** Jupiter の見積りAPIは `dexes` パラメータで
**特定のDEXだけに絞った見積り**が取れる。「Aで買ってBで売る」の往復を実際に見積もれば、
我々の `simulateRoute` と同じ「真実」になる。ただし `lite-api.jup.ag` は**2026年1月31日に廃止**され、
`api.jup.ag` は **`x-api-key` が必須**(無料枠はあるがログインして鍵の発行が必要)。
鍵をもらえたら `SOLANA_JUPITER_KEY` に入れて第2段を作る。

**判断の順序:** 第1段で「連続で残る価格差」が**0件なら、Solana も行き止まり**(作り直す必要なし)。
0でなければ第2段で実行可能性を確かめ、そこで初めて「作るか」を判断する。

**期間:** 50ヶ月・**欠損0**・219万本。**2025-10-10($190億)/ 2024-08-05 / 2022-11-08 の3大暴落を全て含む**

| | 件数 | 勝率 | 平均 | 合計 | 年利 | 下位1% | **最悪** |
|---|---|---|---|---|---|---|---|
| BTCUSDT | 104 | 64.4% | 25.4bps | +26.4% | 6.4% | −322.6bps | **−3.44%** |
| ETHUSDT | 250 | 56.0% | 9.4bps | +23.5% | 5.7% | −513.4bps | **−9.59%** |
| 合計 | 354 | | | +49.9% | **12.1%** | | |

**結論: 戦略は本物。だが「元手に対する年利12.1%」であって、事業ではない。**

元手$100,000 → 年$12,150 = 月$1,012

**危険は尾にある。** ETH の最悪は**1回で−9.6%**。**10倍レバレッジなら証拠金の−96%で一撃退場**。

**往復20bps なら −0.6bps で赤字**。取引所の手数料階層次第で戦略が消える。

**この検証が試していないもの:** オーナーの案の「清算の検知」と「指値」は含まない。
ここで測ったのは**単純に急落を成行で買う版**。清算検知を足す複雑さは、
**この12.1%を上回って初めて意味がある**(検知データは毎秒1件のスナップショットに劣化済み)。

### 10-10. 「逃した見込み$68」の正体を測れるようにした(2026年9月22日 19:30 JST)

| **送信停止の記録**(止めたチェーンの見込み) | × | **○** |

**保存しないと決めたもの(意味が変わるため):**
生存ログの `実行N/M` `内訳` `受信` `失敗段階` は **「このデプロイ以降」** という意味を持つ。
保存すると、その意味が壊れて**別のものになる**。ここは今までどおり毎回ゼロから。
solana の計測は**止めてあるので対象外**(測っていないものは保存しない)。

#### そのまま保存すると数字が嘘になる箇所があった

メインネット歪みの「毎時N回」は `回数 ÷ (今 − startedAt)` で出している。
**`startedAt` をそのまま保存すると、デプロイで止まっていた時間まで分母に入る。**
回数は増えないのに分母だけ伸びるので、**数字が静かに嘘になる**
(このファイルの312行に、まさに同じ失敗の注記がある:毎時47回が23回に半減して見えた)。

→ `startedAt` ではなく **「見張っていた時間そのもの」(`uptimeMs`)を積んで保存**する。
単体テストで「止まっていた1時間が分母に入らないこと」を確かめた
(入れてしまうと 3.3回/時 が 2.5回/時 に化ける)。

終了時(SIGTERM)の書き出しも3つ全部に広げた。

### 10-15. 清算の見張り役を base へ向けた(2026年9月22日 21:45 JST、**オーナーの承認**)

#### 「5行」ではなかった。avalanche 直結が5箇所あった

見積もりを誤って報告したので、実際に直した箇所を残す:

| 箇所 | 何が avalanche 固定だったか |
|---|---|
| `POOL / ORACLE / DATA_PROVIDER` | `AaveV3Avalanche` 直参照 → チェーン別の住所帳 |
| `WSS_URL` | `AVALANCHE_WSS_URL` 固定 → `<CHAIN>_WSS_URL` |
| `V2_FACTORIES` の既定 | **LFJ(Trader Joe)は avalanche の住所**。他チェーンでは**付けない**(存在しない契約に毎回問い合わせて枠を捨てるため) |

| 自己点検 | `WAVAX→USDC` 固定 → そのチェーンの基軸→USDC |
| ログの見出し | `清算AVAX` 47箇所 → `TAG`(チェーン名に追従)。**base を見て「清算AVAX」と出たら数字を読み違える** |

**途中でバグを1つ出した:** 置換の順番を誤り、`${TAG}` が**展開されない素の文字列**に入った
(`"[${TAG}/自己点検] …"`)。バッククォート以外に `${TAG}` が無いかを機械的に確認して直した。

**知らないチェーン名は黙って avalanche に落ちない**ようにした。
向き先を間違えたまま「候補0」と報告するのが、いちばん質の悪い壊れ方。
